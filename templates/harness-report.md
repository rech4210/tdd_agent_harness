# 하네스 리포트 양식

## 언제 쓰나

프로젝트가 슬라이스 몇 개를 마친 뒤, 쌓인 문제 기록(`reports/spec_issues.md`) 중 **유형 = 하네스 · 환경** 을 하네스 저장소로 넘길 때. 사례 하나하나는 문제 기록에 있고, 이 문서는 그것을 **묶음 · 우선순위 · 관찰**로 요약한다. 고치는 일은 하네스 저장소에서 한다 (harness-sync 3절).

## 작성 규칙

| 규칙 | 내용 |
|:---|:---|
| 원문은 문제 기록에 | 재현 방법 · 기대 · 실제는 문제 기록 행에 두고, 여기서는 `#번호` 로 가리킨다 |
| 묶음으로 | 같은 원인의 사례를 한 묶음으로. 묶음마다 "증상 · 제안 · 영향" |
| 우선순위 기준 | 영향(판정 신뢰 > 매 슬라이스 마찰 > 가끔 우회) × 재발(매 슬라이스 / 가끔 / 한 번) |
| 잘 동작한 것도 | 고칠 것만 쓰지 않는다. 하네스가 실제로 막은 것을 따로 적어야 수정이 그것을 깨지 않는다 |
| 관찰은 결론만 | "그래서 무엇을 믿는가" 한 줄 + 근거. 같은 결론을 다시 얻으려면 실험을 반복해야 하는 것만 남긴다 |
| 확인 방법 | 고친 뒤 프로젝트에서 무엇을 다시 돌려 확인하는지 (재현 사례 · 게이트) |
| 도메인 단어 | 하네스로 넘어가는 문장에는 프로젝트 도메인 단어를 쓰지 않는다 |
