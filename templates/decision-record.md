# 결정 기록 양식 (D-xx / O-xx)

## 언제 쓰나

테스트를 쓰기 **전에** 입력과 설정값의 단위 · 범위 · 정밀도 · 검증 위치를 선언할 때(체크리스트 C-A3), 경계값의 소속처럼 논리로 유도되지 않는 선택을 할 때(H2), H3 승인 자료의 열린 질문에 사람이 답할 때, 하네스 장치를 프로젝트 정책으로 켜고 끌 때 쓴다. 동결한 원 명세는 고치지 않고 같은 번호 체계를 이어서 여기에 적는다. 확정한 결정은 고치지 않으며, 바꿀 때는 새 번호로 대체한다.

## 작성 규칙

| 규칙 | 내용 |
|:---|:---|
| 번호 | `D-<번호>` = 확정한 결정, `O-<번호>` = 열린 질문. 번호는 재사용하지 않는다 |
| 불변 | 확정한 D는 고치지 않는다. 바꾸려면 새 D가 "D-xx 대체"를 적고, 옛 D는 기록으로 남긴다 |
| **지키는 테스트 (필수)** | 빈칸 금지. 테스트가 아직 없으면 `(보강 예정, 문제 #<번호>)`. 테스트로 막을 수 없으면 `(없음: <이유>)`라고 적는다. 이것은 **알고 감수하는 위험**의 기록이다 |
| 결정자 | 표 바로 아래에 `결정자: 사람, <YYYY-MM-DD> (<근거 문서 · 질문 번호>)` |
| 층 | 값은 프로젝트 명세, 값을 검사하는 장치는 하네스. 둘이 섞이면 "층" 행으로 나눠 적는다 |
| 값 선언의 빈칸 기준 | 명세 본문에 적혀 있어도 정밀도 · 범위 · 절삭 여부가 정해지지 않았으면 빈칸이다. 빈칸이면 테스트를 쓰지 않고 H2로 돌린다 |
| 상한 없음 | 상한이 없으면 "상한 없음"이라고 **명시**한다. 비워 두면 선언되지 않은 것이다 |

# 결정 기록 (<프로젝트 이름>)

원 명세: `<원 명세 경로>` (태그 `<명세 태그>`). 원 명세는 고치지 않는다. 이후 결정은 번호를 이어 여기에 적는다.

## 형식 A: 짧은 결정 (한 줄)

| ID | 결정 | 고려한 대안 | 이유 | 출처 | 추천과 다름 | 지키는 테스트 |
|:---|:---|:---|:---|:---|:---|:---|
| **D-<번호>** | <무엇을 정했나. 한두 문장> | <버린 대안> | <왜. 계기가 된 사건(문제 #, 검토 보고서)> | <사용자 / 공통 기본값 DEF-## / 모델 기본값 <에이전트>> | <예 / 아니오> | `<테스트 파일>::<테스트 이름>` (<어떤 행 · 어떤 입력 범위>) |

- **승인 효력과 출처는 다르다**: 에이전트의 추천이나 기본값에서 출발했더라도 사람이 승인함으로써 비로소 결정의 효력을 갖는다.
결정자: 사람, <YYYY-MM-DD> (<근거>)

## 형식 B: 긴 결정 (항목 표)

## D-<번호> <제목> (<대체하는 결정이 있으면: D-xx 대체>)

| 항목 | 내용 |
|:---|:---|
| **결정** | <무엇을 정했나> |
| **이유** | <왜. 어떤 실패를 막는가> |
| **고려한 대안** | <대안과 버린 이유> |
| **지키는 테스트** | <테스트 이름. 없으면 `(보강 예정, 문제 #)` 또는 `(없음: 이유)`> |
| **범위 밖** | <이번에 정하지 않은 것과 정할 시점 · 슬라이스> |
| **층** | 장치 = 하네스 / 값 = 프로젝트 |
| **다른 결정과의 관계** | <D-xx와 겹치거나 서로 가려 주는 부분. 한 결정이 다른 결정의 위반을 가리는 상태에 기대지 않는다> |
| **바꾸는 방법** | 새 D로 대체한다. 이 항목을 고치지 않는다 |

결정자: 사람, <YYYY-MM-DD> (<근거>)

## 형식 C: 값 선언 (정의역 표, C-A3)

테스트 대상의 **모든 입력과 설정값**을 한 행씩 적는다. 값 자체는 프로젝트가 정한다. 하네스는 이 선언이 있는지와 테스트가 이 범위를 덮는지만 본다.

| 입력 · 설정 | 단위 | 정밀도 (자르거나 반올림하나) | 최소 | 최대 (또는 "상한 없음") | 추가 조건 | 검증 위치 |
|:---|:---|:---|:---|:---|:---|:---|
| `<이름>` | <단위> | <받은 정밀도 그대로 / 경계에서 명시적으로 정규화> | <값> | <값 / 상한 없음> | <다른 값과의 관계, 허용 집합> | <생성 시 도메인이 거부 / 함수가 계산 전에 거부 / 어댑터가 정규화> |

- **검증 위치:** <어느 경로로 들어와도 같은 규칙이 적용되는가>
- **지키는 테스트:** 경계값 표(최소 · 최대 ± 최소 해상도), 매개변수 가변 성질 테스트(C-A5), 거부 영역 전체(C-A6)
- **바꾸는 방법:** 요구가 바뀌면 새 D로 대체한다

결정자: 사람, <YYYY-MM-DD>

## 열린 결정 (O-xx)

| ID | 질문 | 왜 사람이 정해야 하나 | 막고 있는 것 | 정할 시점 |
|:---|:---|:---|:---|:---|
| **O-<번호>** | <질문> | <사업 · 법 · 외부 시스템 · 관행에 달린 이유> | <답이 없어서 쓸 수 없는 테스트 · 슬라이스> | <슬라이스 ID 전 / H3에서> |

- O가 확정되면 형식 A 또는 B로 D를 쓰고, O 행의 끝에 `→ D-<번호>`를 붙인다. O 행은 지우지 않는다.

## 기록 전 확인

- [ ] 모든 D에 "지키는 테스트"가 있다 (빈칸 없음)
- [ ] 값 선언에 단위 · 정밀도 · 최소 · 최대 · 검증 위치가 있다 ("상한 없음"도 명시)
- [ ] 기존 D를 고치지 않았다 (대체는 새 번호)
- [ ] 결정자와 날짜가 있다
