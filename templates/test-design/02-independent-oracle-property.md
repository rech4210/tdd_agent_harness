# 02 독립 오라클 성질 테스트

| 항목 | 내용 |
|:---|:---|
| 체크리스트 | C-A1, C-A4, B-1, B-6 |
| 함께 쓰는 것 | 01 경계값 표, 03 경계 근처 생성기, 06 매개변수 가변 |

## 목적

계산 결과의 **값**이 선언된 **정의역 전체**에서 명세와 같은지 확인한다. 정답은 구현과 **다른 방법**(느리지만 명백한 방법)으로 테스트 안에서 계산한다.

오라클은 **기대값 표 · 성질**로 작성하는 것을 기본으로 한다. 불가피하게 계산 오라클이 필요하면 구현과 **다른 알고리즘**임을 명시해야 한다. 또한 계산 오라클이 든 테스트 지원 모듈은 **구현자에게 주지 않는다** (격리 저장소 제외 대상).

> **참조 구현 독립성 규칙 (V4-14)**:
> 테스트 작성자와 같은 계열이 만든 참조 구현은 독립 근거로 세지 않는다 (세 구현이 일치해도 같은 계열이면 같은 맹점을 공유할 수 있다).

## 언제 쓰나

- 결과 값을 계산하는 순수 로직 (금액 · 수량 · 구간 · 목록)
- 예시 표만으로는 "그 예시에서만 맞는 구현"을 막을 수 없을 때 — 사실상 항상
- 성질(대칭, 단조성, 보존)만으로는 "그럴듯하지만 틀린 답"을 못 잡을 때

## 무엇을 막나

| 실패 | 일반화된 사례 |
|:---|:---|
| 예시 값 하드코딩 | 경계값 표와 성질 테스트(보존 · 단조성)가 있었는데도, 표에 나온 입력에서만 규칙을 지키는 구현이 전부 통과했다. 정의역 전체의 오라클 비교가 그 구멍을 막았다 |
| 정의역 일부에서 자르기 (C-A1) | 성질 테스트가 "현실적인" 범위만 뽑아서, 그 위에서 값을 자르는 구현이 통과했다. 명세는 상한을 정하지 않았다 |
| 오라클과 구현이 같은 버그 공유 (B-6) | 오라클이 검사 대상의 메서드를 재사용하면 둘이 같이 틀린다 |
| 값 객체 비교에 기댐 (C-A4) | 값 객체의 `==`가 항상 참이면 그 위의 모든 비교가 공허하다 |
| 오라클 유출 (계산 오라클 공유) | 계산 오라클이 든 테스트 지원 모듈을 구현자가 그대로 옮겨 오라클과 구현이 같은 맹점을 공유했다 (이슈 #30) |

## 최소 구조

```
오라클(입력) = 1. 기대값 표 · 성질이 기본
               2. 계산 오라클이 필요하면 구현과 다른 알고리즘임을 명시
               3. 대상 모듈을 import 하지 않는다 (데이터 타입 생성자는 예외)
               4. 계산 오라클이 든 테스트 지원 모듈은 구현자(격리 저장소)에게 주지 않는다
               - 가능하면 구현과 다른 형태 (조건문 ↔ 표 조회, 구간 비교 ↔ 집합 교집합, 반복 ↔ 닫힌 식)
생성기    = one_of(
              정의역 일반 범위,
              정의역의 큰 값 (상한 없음이면 매우 큰 값까지 별도 가지),
              경계 근처 (03)
            )
성질      = 모든 입력 x: 구현(x)의 출력 전체 == 오라클(x)
            비교는 원시 값으로 (값 객체의 == 에 기대지 않는다)
```

## 게으른 구현 예

| 게으른 구현 | 이 테스트가 잡는 방법 |
|:---|:---|
| `if x == 예시값: return 기대값` | 무작위 입력 수백 개가 예시 밖에서 오라클과 어긋난다 |
| 큰 입력에서 값을 상한으로 자름 | 큰 값 가지가 상한 위 입력을 뽑는다 |
| 값만 맞추고 규칙 ID · 파생 값은 아무렇게나 | 출력 전체를 비교한다 |
| 값 객체 `==`를 항상 참으로 | 원시 값 비교라서 영향받지 않는다 |

## 흔한 실수

| 실수 | 결과 |
|:---|:---|
| 오라클이 구현을 복사 · 재사용 | 같은 버그를 공유한다 |
| 테스트 작성자와 같은 계열의 참조 구현에 기댐 | 세 구현이 일치해도 같은 계열이면 같은 맹점을 공유할 수 있어 독립 근거가 되지 못한다 |
| 계산 오라클 모듈을 구현자에게 노출 | 구현자가 오라클 코드를 재사용/복사하여 같은 맹점을 공유한다 (격리 저장소에 주지 않는다) |
| 생성기 범위가 정의역보다 좁음 | 범위 밖에서 틀리는 구현이 통과 (C-A1) |
| 큰 값을 한 범위에 섞어 뽑음 | 작은 값이 거의 안 나오거나 그 반대. 가지를 나눠 `one_of`로 |
| 오라클에 상수 · 기본값을 박음 | 매개변수를 무시하는 오라클이 된다 (06) |
| 결과의 일부 필드만 비교 | 나머지 필드를 틀리는 구현이 통과 |

## Python 참조 구현

```python
"""<대상> 독립 오라클. 지키는 결정: D-xx (규칙 표), D-yy (정의역: 0 이상 정수, 상한 없음)."""
from hypothesis import given
from hypothesis import strategies as st

from mypkg.pricing import price_for  # 예시: 프로젝트의 대상으로 바꾼다

# 정의역 전체: 일반 범위와 매우 큰 범위를 따로 뽑는다 (D-yy)
quantities = st.one_of(
    st.integers(min_value=0, max_value=10_000),
    st.integers(min_value=10_001, max_value=10**15),
)

# 명세 표를 데이터로 옮긴다 (구현의 조건문과 다른 형태). 예시 값.
TABLE = [(100, 8, "BULK"), (10, 9, "MID"), (0, 10, "BASE")]


def oracle(q: int) -> tuple[int, str]:
    _, unit, rule = next(row for row in TABLE if q >= row[0])
    return q * unit, rule


@given(quantities)
def test_matches_independent_oracle(q):
    got = price_for(q)
    assert (got.total.value, got.rule_id) == oracle(q)  # 원시 값으로 비교
```
