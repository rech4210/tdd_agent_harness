# 작업 지시서 양식 (구현자용, 격리 전제)

## 언제 쓰나

H3 승인과 테스트 잠금이 끝난 뒤, 구현자에게 슬라이스 구현을 맡길 때 쓴다. 이 지시서는 구현자와의 **유일한 계약**이다. 구현자는 격리 저장소에서 이 지시서와 잠긴 테스트만 보고 일하며, 하네스의 방어 장치(우회 패턴, 고친 구멍, 레드팀 기록, 결정의 배경 보고서)를 모른다. 판정은 구현 세션 밖에서 lead가 게이트 명령으로만 한다. 절차는 `docs/isolated-delegation.md`.

## 작성 규칙 (lead용. 지시서에는 넣지 않는다)

| 규칙 | 내용 |
|:---|:---|
| 방어를 적지 않는다 | 우회 패턴 목록, 과거 우회 사례, 회귀 후보, 레드팀 결과를 지시서에 쓰지 않는다. 구현자의 정보 조건이 바뀌면 측정이 오염된다 |
| 근거는 ID로 | 결정 · 불변식은 ID만 인용하거나 규칙 자체를 옮긴다. 배경 설명이나 요약은 쓰지 않는다 (요약은 원문과 어긋난다) |
| 판정 가능한 말만 | "깔끔하게", "적절히"처럼 기계가 판정할 수 없는 말을 쓰지 않는다. 그런 기준은 게이트(정적 품질)나 사람 검토로 옮긴다 |
| 목록은 닫혀 있다 | 읽기 · 쓰기 허용 목록에 없는 것은 금지다. "등"으로 끝내지 않는다 |
| 공개 API는 테스트와 같다 | 테스트가 호출하는 이름 · 인자 · 예외를 그대로 적는다 |
| 사람은 직접 지시하지 않는다 | 사람의 의도는 결정 · 테스트 승인을 거쳐서만 구현에 닿는다. 지시서 밖의 대화 지시는 하지 않는다 |
| 일치 검사 | `agent`는 배정 파일과 같아야 한다(게이트 GA). 쓰기 허용 목록은 역할 권한 표의 범위 안이어야 한다(게이트 G0) |
| 회차는 원인별 | `max_rounds` 는 구현자 원인 회차만 센다. 판정 명령에 `--cause implementer|test|harness` 지정 (테스트 보강 · 재잠금 뒤 회차는 `test`, 하네스 문제는 `harness`) |
| G3 실패 판정 | G3 실패는 테스트 작성자가 먼저 "테스트 빈틈 / 구현자의 쓸모없는 코드"를 판정한다. 구현자에게 넘길 때 기본 문구: "명세가 요구하는 분기는 지우지 말고 보고" |

아래부터 복사해서 쓴다.

# <슬라이스 ID> <슬라이스 이름> 구현

> 이 문서가 당신(구현자)과의 유일한 계약이다. 여기 적히지 않은 것은 하지 않는다.
> 막히면 추측해서 진행하지 말고 §6대로 멈추고 보고한다.

```yaml
id: <슬라이스 ID>
role: implementer
agent: <에이전트 이름>          # 배정 파일과 같아야 한다
family: <실제 실행 계열>        # 위임 뒤 lead 가 적는다 (예: 위임 기록 meta.json 의 family). GA 가 agents.toml 과 대조
job: <위임 job 이름>            # config/delegation.toml 이 있으면 GA 가 이 job 의 위임 기록에서 계열을 읽는다 (family 대신 또는 함께)
base: <기준 태그>               # 테스트 잠금 + 이 지시서 확정 커밋
slice: <슬라이스 ID>            # 슬라이스 정의의 키
shell: none                     # 명령을 실행하지 않는다. 판정은 세션 밖에서 한다
feedback: python harness/run_gates.py --feedback --role implementer --base <ID>-base --wo <ID> # 위임 도구가 판정 전에 에이전트 밖에서 돌려 결과를 돌려준다 (커버리지는 없다)
max_rounds: <N>                 # 넘으면 사람에게. 구현자 원인 회차만 센다 (판정 실행만 세며, 판정 전 피드백은 회차가 아니다)
```

## 0. 작업 환경

- 작업 공간에는 이 작업에 필요한 파일만 있다. §2에 없는 파일을 찾거나 만들지 않는다.
- 판정은 이 작업 공간 밖에서 한다. 이 작업 공간에서 테스트가 통과했다는 보고는 판정에 쓰이지 않는다.

## 1. 목표

`<테스트 파일 경로>`의 테스트가 전부 통과하는 제품 코드를 쓴다. 이미 통과하는 다른 테스트(`<회귀 테스트 범위>`)도 계속 통과해야 한다. Green과 Refactor를 한 번에 해도 된다.

## 2. 읽을 수 있는 것 (이 밖의 파일은 읽지 않는다)

| 파일 | 용도 |
|:---|:---|
| `<테스트 파일 경로>` | **명세.** 읽기만 한다 |
| `<공통 픽스처 · 다른 테스트>` | 이미 구현된 부분의 명세. 읽기만 한다 |
| `<구조 규칙 테스트>` | 레이어 규칙. 읽기만 한다 |
| `<기존 소스 경로>` | 사용할 수 있다 |
| 이 문서 | 계약 |

## 3. 만들 것

### 쓸 수 있는 파일 (이 밖은 쓰지 않는다)

```
<새 파일 경로>        (새 파일)
<기존 파일 경로>      (<무엇을 추가하나>. 기존 내용은 바꾸지 않는다)
```

### 공개 API (테스트가 호출하는 이름. 바꾸지 않는다)

| 이름 | 의미 |
|:---|:---|
| `<모듈>.<예외 이름>` | <언제 내는가> |
| `<타입>(<인자>)` | <받은 값을 그대로 속성으로 가진다 / 생성 시 검증한다> |
| `<함수>(<인자>, <설정>=<기본값>)` | <아래 규칙대로 무엇을 돌려준다> |

### 입력 · 설정값 검증 (위반이면 `<예외 이름>`)

| 대상 | 허용 (결정 D-xx 그대로) |
|:---|:---|
| `<인자 · 속성>` | <단위, 최소 ~ 최대, 추가 조건> |

<언제 검증하는가: 생성 시 / 계산 전에 항상(다른 조건과 무관하게)>

### 계산 규칙

1. <규칙. 테스트의 오라클과 같은 순서 · 같은 말로>
2. <규칙>
3. <결과의 순서 · 형식>

### 규칙

- <정밀도: 받은 정밀도로 비교한다. 자르거나 반올림하지 않는다 — 해당할 때>
- <의존 규칙: 이 레이어가 import할 수 있는 것의 닫힌 목록>
- 현재 시각 · 난수 · 환경변수를 직접 읽지 않는다. 필요한 값은 인자로만 들어온다.
- 테스트 도구를 import하지 않는다.
- 테스트마다 시간 제한이 있다. 끝나지 않는 계산은 실패로 판정된다.

## 4. 완료 조건 (전부 기계 판정, 세션 밖에서 실행)

```
python harness/run_gates.py --role implementer --base <기준 태그> --slice <슬라이스 ID> --cause implementer|test|harness
```

- [ ] 마지막 줄이 `SLICE PASS` (범위 밖 게이트: `<SKIP 게이트 목록>`)
- [ ] 판정 기준: <게이트 목록과 각 기준. 예: G2 테스트 전체, G3 `<파일>` 분기 커버리지 <임계값>, G6 변이 점수 <임계값> 이상, G7 정적 품질>

판정 명령에 `--cause implementer|test|harness` 를 붙여 원인을 남긴다 (구현자 판정은 `implementer`, 테스트 보강 · 재잠금 뒤 회차는 `test`, 하네스 문제는 `harness`). `max_rounds` 는 `implementer` 원인 회차만 센다. 이 명령의 결과만이 완료의 근거다. 자기 보고, 작업 공간 안의 테스트 실행 결과는 근거가 아니다.

## 5. 하지 않는 것

- 테스트, 하네스, 도구 설정 파일, 저장소 설정 파일, 지시서, 다른 보고서를 바꾸지 않는다: `<보호 경로 목록>`. `reports/**` 쓰기는 이 작업의 결과 보고 파일(§7 형식)만
- §3의 쓸 수 있는 파일 밖의 제품 코드를 바꾸지 않는다.
- 테스트에 나온 특정 값을 조건문의 비교 대상으로 쓰지 않는다. 허용 범위는 이름 있는 상수로 둔다.
- 테스트를 건너뛰거나, 검사(커버리지 · 변이 · 타입)를 제외하는 주석을 쓰지 않는다.
- 테스트 실행 환경을 감지하는 코드를 쓰지 않는다.
- 계약 밖 처리는 **진입 함수 한 곳**에서 정해진 일반 거부로 바꾸는 것만 허용한다 (명세의 계약 밖 기본 동작). 그 밖에서 예외를 잡아 삼키지 않는다 (G3 미덮임 예외는 그 변환 분기뿐이며 판정자가 diff 에서 확인한다).
- 커버리지(G3)를 맞추려고 명세가 요구하는 분기나 방어 코드를 임의로 지우지 않는다 (§6대로 보고).

## 6. 막혔을 때

**규칙을 어겨서 끝내지 말고 멈춰서 보고한다.** `blocked`는 실패가 아니다. 명세의 구멍을 찾은 것이다.

- 테스트 두 개가 동시에 만족될 수 없다고 판단되면: 두 테스트 이름과 이유를 적고 멈춘다.
- 테스트와 이 문서가 다르면: 고치지 말고 두 위치를 적고 멈춘다.
- 명세가 답하지 않는 상황이면: 추측해서 구현하지 말고 질문을 적는다.
- `max_rounds`를 넘으면 (구현자 원인 회차 기준): 마지막 판정 실패 이유를 적고 멈춘다.
- 명세가 요구하는 분기는 커버리지(G3)를 통과시키기 위해 지우지 말고 보고한다.

## 7. 보고 형식

status: done | blocked
