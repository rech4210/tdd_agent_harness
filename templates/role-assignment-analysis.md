# 역할 배정 분석 양식

## 언제 쓰나

슬라이스별 역할 배정(어느 에이전트가 테스트 작성 · 구현 · 변이 분류 · 레드팀을 맡나)을 바꾸는 가설을 세우고 검증할 때 쓴다. 하네스는 **역할과 분리 제약만** 고정하고, 배정은 운영이다. 배정은 슬라이스 경계에서만 바꾸고 이유를 배정 파일에 남긴다. 한 슬라이스의 결과로 결론 내리지 않고, 같은 종류의 슬라이스를 모아 KPI로 비교한다.

## 고정 규칙 (하네스)

| 규칙 | 내용 |
|:---|:---|
| 분리 제약 (기본) | 같은 슬라이스에서 다음 쌍은 **다른 모델 계열**: 테스트 작성자 ↔ 구현자, 구현자 ↔ 검토자, 테스트 작성자 ↔ 변이 분류자, 테스트 작성자 ↔ 레드팀 |
| 하네스 설계자는 구현자가 아니다 | 방어 장치 · 고친 구멍 · 남은 빈틈을 아는 쪽이 구현하면 "하네스가 구현자를 붙잡는가"라는 측정이 의미를 잃는다. 같은 지식이 공격자 · 검토자에게는 강점, 구현자에게는 오염원이다 |
| 자기 평가 주의 | 평가 대상인 에이전트가 자기 역할을 판단하면 과대평가 위험이 있다. 결론은 가설로 둔다 |
| 변경 시점 | 슬라이스 경계에서만. 진행 중인 슬라이스는 바꾸지 않는다 |
