# 문제 기록 양식

## 언제 쓰나

구현 · 판정 · 위임 · 검토 중에 발견한 문제를 적는다. 원 명세나 결정을 직접 고치지 않고 "발견 → 사람 결정 → 결과(새 D, 테스트 보강, 하네스 수정)"의 순서로 남긴다. 이 기록은 실험 데이터다. 명세 유형의 건수가 "명세 변경 건수", 하네스 유형의 건수가 "하네스 결함 건수"가 되고, 하네스 · 환경 원인으로 실패한 판정 실행은 구현자의 재시도 횟수에서 뺀다.

## 유형

| 유형 | 무엇에 대한 문제인가 | 일반적인 예 | KPI 처리 |
|:---|:---|:---|:---|
| **명세** | 불변식 · 결정 · 테스트의 **내용** | 게으른 구현이 통과함, 정밀도 · 상한이 선언되지 않음, 경계 행 누락 | "명세 변경 건수"에 들어감 |
| **하네스** | 게이트 · 역할 · 실행기 · 잠금 · 측정 범위 | 이전 실행 산출물을 읽어 통과, 측정 범위 밖으로 로직 이동, 판정이 끝나지 않음 | "하네스 결함 건수". 해당 실행은 구현자 KPI에서 제외 |
| **환경** | OS · 도구 · 의존성 · 위임 도구 | 도구가 OS를 지원하지 않음, 위임 도구의 거짓 성공, 실행 기계의 현지 설정에 결과가 좌우됨 | 구현자 KPI에서 제외 |

## 작성 규칙

| 규칙 | 내용 |
|:---|:---|
| 발견자 | 역할과 단계를 함께 적는다. 예: `테스트 작성자 (H3 준비)`, `레드팀 (재현)`, `lead (세션 밖 판정)` |
| 무엇이 문제인가 | 관찰한 사실과 재현 조건. 추측은 "추정"이라고 표시 |
| **사람 결정** | **사람만 채운다.** 비어 있으면 `대기`. 대기 중인 문제가 있는 슬라이스는 닫지 않는다 |
| 결과 | 무엇을 바꿨나(커밋, 새 D, 보강 테스트)와 **어떻게 확인했나**(재판정, 변이가 잡힘, 후보가 실패) |
| 판정 장치 변경 | 잠금 해시 방식 등이 바뀌면 결과에 `재잠금 필요`와 테스트 내용 불변 근거(`git diff <커밋> -- <테스트 경로>`가 비어 있음)를 적는다 |
| 위임 도구 보고 | 위임 도구의 성공 보고는 결과의 근거로 쓰지 않는다 |
| 수정 금지 | 지우거나 고치지 않는다. 틀린 기록은 새 행으로 정정하고 원래 번호를 인용한다 |

## 자주 나오는 하네스 · 환경 결함 (일반화된 사례)

새 프로젝트에서 처음 판정을 돌릴 때 먼저 의심할 것들이다.

| 증상 | 원인 | 고친 방향 |
|:---|:---|:---|
| 소스가 없는데 커버리지 · 변이 게이트가 통과 | 이전 실행의 산출물을 읽음 | 실행 시작 시 이전 산출물 삭제 |
| 다른 체크아웃에서 "테스트 변조"로 판정 | 잠금 해시가 줄바꿈에 민감 | 줄바꿈을 맞춘 뒤 해시. 사람이 재잠금 |
| 변이가 0개인데 게이트 통과 또는 import 실패 | 변이 도구가 대상 파일만 복사 | 패키지 전체를 함께 복사하도록 도구 설정 |
| 판정이 실패하지 않고 멈춤 | 끝나지 않는 구현 | 게이트 단위 · 테스트 단위 시간 제한. 넘으면 실패 |
| 현지 설정에 기대는 변이가 살아남음 | 실행 기계의 환경(시간대 · 로캘)이 서비스 환경과 같음 | 게이트 환경을 서비스와 **다른** 값으로 고정 |
| 회귀 장치가 모든 게으른 후보를 "통과"로 보고 | 테스트 실행기의 import 경로 설정이 실제 구현을 먼저 import | 실행기 설정을 명령줄에서 덮어쓰고 import 대상을 출력 |
| 위임 결과가 "성공"인데 변경이 없음 | 권한 거부로 아무것도 못 함 | diff와 게이트로만 판단 |
| 다음 작업자의 G0가 "허용 경로 밖 변경"으로 실패 | 위임 도구가 작업 트리에 기록 파일을 남김 | 기록 위치를 저장소 밖으로, 또는 로컬 제외 |
