# S5 테스트 검토 지시 양식 (품질 검토자용)

lead 가 슬라이스마다 이 양식을 채워 검토자(adversary)에게 준다. 목적은 **최소 맥락으로 새 결함만** 찾게 하는 것이다(지시서 §8.1: 기본 후보 통합 · 최소 유효 맥락 · 중복 제거 · 새 결함 탐지 실적).

## 채우는 칸 (lead)

| 칸 | 내용 |
|:---|:---|
| 슬라이스 · 회차 | `<ID>` · `<N>` 회차 (위험도 `<low|medium|high>` — low 는 최대 1회차) |
| 읽을 것 (닫힌 목록) | `specs/<기능>/spec.md` 의 해당 FR · INV, `tests/<경로>`, 결정 `<D-## 목록>`. **그 밖의 파일 · 이전 대화 · 구현 소스는 주지 않는다** |
| 이미 넣은 기본 후보 | `unbounded` · `reject-preserve` 후보 목록(체크리스트 B-10). 이 유형의 일반론은 지적하지 말고, 빠진 **구체 경로**만 지적한다 |
| 이전 회차 지적 (중복 금지) | `<ID · 한 줄>` 목록. 같은 지적을 다시 내지 않는다. 반영이 틀렸으면 “재지적: <ID>” 로 쓴다 |

## 검토자에게 주는 지시

1. 이 테스트를 통과하면서 명세를 어기는 **가장 게으른 구현**을 찾는다. 후보마다 피해 시나리오와 해결 방향(테스트 추가 / 명세 관리)을 한 줄씩.
2. 승격 규칙에 맞지 않는 코너 케이스는 스스로 기각한다(근거 = 규칙).
3. 출력 표:

| ID | 후보 (게으른 구현) | 어기는 FR · INV · D | 새 지적 / 재지적 | 피해 | 해결 방향 |

4. 마지막 줄: “계약 안 결함 K (새 M · 재지적 K−M)”.

## 기록 (lead)

받아들인 지적은 **보강 전 테스트로 그 후보가 통과하는지 먼저 실행**해 실제 빈틈인지 확인한 뒤 반영한다. 기록:

```
python harness/mark.py review <검토자> --wo <ID> --round <N> --defects <K> --new-defects <M>
```

`kpi.py` 의 “검토 비용 (위험도별)” 표가 회차 · 새 결함 · 검토 시간 · 토큰을 위험도별로 모은다. 새 결함이 0 인 회차가 나오면 그 슬라이스의 검토를 끝낸다.
