# H3 테스트 승인 자료 양식

## 언제 쓰나

테스트 작성자가 슬라이스의 테스트를 쓰거나 보강한 뒤, 사람이 그 테스트를 승인하고 잠그기(H3) **전에** 쓴다. 사람이 테스트 전체를 정독하지 않아도 "무엇을 더했고, 어떤 게으른 구현을 실제로 막는지, 무엇을 막지 못하는지, 사람이 무엇을 정해야 하는지"를 한 장으로 판단하게 하는 것이 목적이다. 테스트를 다시 고치면(변이 판정 후 보강 등) 같은 자료를 갱신해 재승인 · 재잠금한다.

## 작성 규칙

| 규칙 | 내용 |
|:---|:---|
| 결론 먼저 | 머리말 마지막 줄에 권고와 선행 조건 |
| 실행으로 확인 | §2의 결과는 실제로 돌린 결과만. 돌리지 않은 후보는 `미실행`으로 적는다 |
| 정상 빌드 행 필수 | §2 첫 행은 정상 빌드. 이 행이 없거나 통과하지 않으면 표 전체가 무효다 (회귀 장치의 공허한 참) |
| 정직한 한계 | 테스트가 동작으로 구별할 수 없는 후보는 "잡지 않는 것"에 적고, 누가 대신 보는지 적는다 |
| 질문은 제안과 함께 | 사람이 정할 것마다 제안과 이유를 붙인다. 답은 결정 기록(D-xx)으로 옮긴다 |
| 근거 칸 | 결정(D) · 불변식(INV) · 요구 ID · 체크리스트 항목(C-A)을 ID로 적는다. 요약하지 않는다 |

## 6. 승인 절차

1. (lead) 이 자료를 내기 직전 `wait-start H3`
2. Q1 ~ Qn에 답한다 → 결정 기록에 D-xx로 남긴다
3. 체크리스트 기본 질문과 위 C-A 항목을 확인한다
4. 바뀐 테스트와 명세 확인: `git show <이 자료 커밋> -- <테스트 파일 경로> <명세 파일 경로>`
5. (lead) 사람의 승인 답을 받은 직후 `wait-end H3 --decisions <N>`
6. (lead) 잠금: `python harness/check_protected_paths.py --write-lock` (**테스트와 명세가 바뀌었을 때**: `locked = ["tests/**", "specs/**"]`)
7. 지시서를 확정해 커밋하고 기준 태그: `git tag -a <슬라이스 ID>-base -m "<테스트 · 명세 잠금 + 지시서 확정>"` ("잠금 + 지시서 확정 커밋 = 기준 태그 `<슬라이스 ID>-base`")
