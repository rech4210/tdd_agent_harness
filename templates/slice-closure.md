# 슬라이스 종료 기록 양식

## 언제 쓰나

세션 밖 판정이 통과하고, 생존 변이 판정(H9)과 이 슬라이스에서 나온 문제의 "사람 결정"이 모두 채워진 뒤 슬라이스를 닫을 때 쓴다. 닫는 주체는 HD-47 을 따른다(H9 대상이 없으면 lead, 있으면 사람이 H9 뒤). 판정 결과뿐 아니라 경과(몇 번 돌았나, 무엇이 누구 탓이었나), KPI, 확인한 것과 확인하지 않은 것, 이 슬라이스가 남긴 결정 · 장치를 한 장에 남긴다. 기록을 커밋한 뒤 종료 태그를 단다.

## 작성 규칙

| 규칙 | 내용 |
|:---|:---|
| 닫는 사람 | 게이트 통과이고 사람 판정이 필요한 생존 변이(H9)가 없으면 lead, 있으면 사람이 H9 뒤 종료(HD-47). 기록은 누구든 |
| 판정 근거 | 세션 밖 판정의 실행 커밋과 수치. 에이전트 보고는 쓰지 않는다 |
| 실패 귀속 | 판정 실패마다 원인을 구현자 / 테스트 / 하네스 / 환경으로 나눈다. 구현자 원인이 아니면 구현자 KPI에서 뺀다 |
| 기준선 여부 | 기준 태그 이후 테스트 · 하네스 · 설정을 바꾸지 않고 통과했으면 "기준선", 아니면 "참고값"과 이유 |
| 확인하지 않은 것 | 반드시 한 칸 이상. 레드팀 생략, 사람 시간 미기록 등 |
| 처음 드러난 단계 | 같은 결함이 여러 단계에서 보여도 처음 드러난 단계 하나에만 센다 |
| 질문과 결함을 나눈다 | 명세 질문(사람 결정으로 간 것)과 테스트 · 구현 · 하네스 결함은 다른 줄 |
| 성격 한 줄 | 무엇의 종류인지(예: 제품 의미 / 경계 / 입력 표현 / 사본 / 시간대 / 게이트 상호작용) |
| 뒤집힘 | 질문 단계 뒤에 사람이 결정을 뒤집은 수를 따로 센다 (0 이 아니면 명세 단계의 질문 범위가 부족했다는 신호) |
| 태그 | annotated, 메시지에 "무엇이 증명되었나" 한 줄 |
