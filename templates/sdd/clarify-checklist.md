# 명확화(clarify) 결과 승격 점검표

## 목적

Spec Kit 의 `clarify` 세션에서 도출된 질문 · 답변(`## Clarifications`)과 미결정 항목들을 사람이 검토하여, 결정 기록(`reports/decisions.md` 의 `D-##`) 또는 사람 개입 구간(`H#`)으로 승격할 때 사용하는 점검표다.

## 작성 및 점검 규칙

1. **에이전트는 D 번호를 손으로 만들지 않는다**: 답변 줄의 `→ [결정 대기]` 를 사람이 직접 `reports/decisions.md` 에 기록하고 `→ D-##` 로 승격한다. **일괄 승인(옵트아웃)**: 에이전트가 질문마다 추천 · 근거 1줄 · 대안 1줄을 담은 패키지(`reports/clarify/B-<번호>.md`, 틀 `templates/sdd/clarify-package.md`)를 만들어 사람에게 보이고, 사람이 승인하면(질문별 대안 채택 · 건너뛰기 가능) `python harness/decisions.py expand --package … --approval "<승인 원문>" --by user [--alt Q# …] [--skip Q# …]` 가 질문마다 D-## 를 원문 그대로 전개한다. 추적 게이트(`batch_integrity`)가 기록 = 패키지(해시 · 원문)를 확인한다. **위험도 높음 슬라이스와 사람 개입 구간(H#)으로 가는 질문은 일괄 패키지에 넣지 않는다** — 하나씩 묻는다.
2. **값 선언 필수**: 명세 본문에 기술되어 있더라도 단위 · 범위 · 정밀도 · 검증 위치가 선언되지 않았으면 미결정이다 (C-A3).
3. **경계값 표 동기화**: 결정된 값은 명세의 `## Boundary tables` 칸에 `D-##` 로 반영한다.

## 승격 점검 항목

| # | 점검 항목 | 점검 내용 | 승격 대상 (D-## / H#) | 대응 체크리스트 |
|:---|:---|:---|:---|:---|
| 1 | 입력 단위 및 표현 정밀도 | 모든 수치 · 시간 · 금액 입력에 정수/실수 단위, 반올림/절삭 규칙, 최소 해상도가 확정되었는가? | `D-##` (단위 · 정밀도) | `C-A3`, `C-A1`, `B-3` |
| 2 | 정의역 경계 및 상한 유무 | 입력값의 최소 · 최댓값이 정해졌는가? 상한이 없다면 "상한 없음"이 명시되었는가? | `D-##` (범위 선언) | `C-A1`, `C-A3` |
| 3 | 경계값 소속성 (초과/이상) | 경계 지점이 유효 영역에 포함되는지(이상/이하) 제외되는지(초과/미만) 확정되었는가? | `D-##` (경계 판정) | `C-A2`, `B-3` |
| 4 | 거부 조건 및 실패 상태 | 잘못된 입력에 대해 어떤 오류로 거부하는지, 거부 시 상태 불변이 보장되는지 정해졌는가? | `D-##` (거부 규약) | `C-A6`, `B-4` |
| 5 | 값 객체 동등성 및 연산 | 엔티티/값 객체의 비교(`==`, `<`) 규칙과 원시 값 변환 기준이 명시되었는가? | `D-##` (객체 규약) | `C-A4`, `C-A7` |
| 6 | 부수효과 횟수 및 멱등성 | 외부 통신, 저장소 쓰기, 이벤트 발행의 호출 횟수와 재시도/중복 처리 규칙이 확정되었는가? | `D-##` 또는 `H4`/`H6` | `B-5`, `B-7` |
| 7 | 실행 환경 및 시간 상한 | 시간 지연 허용치, 동시성 한계, 타임아웃 상한이 본질적 이유에 근거하여 확정되었는가? | `D-##` 또는 `H10` | `C-A8`, `B-7` |
| 8 | 매개변수 가변성 허용 | 기본값 외에 다양한 파라미터 조합이 가능한지, 제약 조합이 확정되었는가? | `D-##` (매개변수 범위) | `C-A5` |
| 9 | 잔여 미결정 마커 제거 | 명세 본문에 `[NEEDS CLARIFICATION]` 표시가 0건인가? (남아있다면 슬라이스 제외 또는 추가 명확화) | `H2` 추가 확인 | `B-1`, `B-8` |

## 승격 확인 절차

- [ ] 1. `specs/<기능>/spec.md` 의 `## Clarifications` 모든 항목이 `→ D-##` 또는 `→ H#` 로 종결되었는지 확인
- [ ] 2. `## Boundary tables` 의 미결정 칸이 해당 `D-##` 로 갱신되었는지 확인
- [ ] 3. `reports/decisions.md` 에 새 `D-##` 항목들이 "지키는 테스트" 항목과 함께 올바르게 기록되었는지 확인
- [ ] 4. 명세 본문에 `[NEEDS CLARIFICATION]` 마커가 0건인지 확인 (GT 검사 통과 선행 조건)
