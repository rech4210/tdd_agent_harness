# 하네스 인계 폴더 규칙 (`reports/harness-handoff/`)

## 왜

하네스 결함을 고치는 쪽(하네스 저장소)은 "Red 판정 사례"부터 쓴다. 그 재료가 대화 · 임시 폴더에만 있으면 세션이 끝날 때 사라진다. 이 폴더는 **재현 가능한 근거**를 저장소 안에 남긴다 (이어 가기 정보는 저장소 안에만).

## 구성

| 경로 | 내용 | 규칙 |
|:---|:---|:---|
| `WORK-ORDER.md` | 하네스 쪽 작업 지시서. 단계 · 항목(H-##)마다 문제 · 재현 · 고칠 곳 · 방향 · Red 사례 · 완료 조건 | 프로젝트 도메인 단어 없이. 근거는 문제 기록 `#번호` 와 `repro/` 파일로 |
| `repro/r<N>_<짧은 이름>.py` | 실행 가능한 최소 재현. 표준 라이브러리와 테스트 도구만 | 첫 docstring 에 이슈 번호 · 사용법 · 기대 결과 · 하네스 수정 뒤 확인 방법. 프로젝트 제품 코드를 import 하지 않는다 |
| `repro/r<N>_<짧은 이름>.md` | 코드로 못 만드는 절차 재현 (저장소 구조가 필요한 게이트 등) | 절차 · 실제 · 기대 · 수정 뒤 확인 |
| `templates/` | 하네스 저장소 `templates/` 에 넣을 양식 초안 | 그대로 복사 가능한 형태 |

## 넣지 않는 것

| 자료 | 이유 |
|:---|:---|
| 프로젝트 제품 코드 · 테스트 복사본 | 하네스 판정 사례는 최소 사례로 새로 쓴다 (Core 는 도메인을 모른다) |
| 격리 위임에 쓰는 참조 구현 · 변이 스크립트 | 정답 구현이다. 필요하면 이 폴더 밖(`reports/selfcheck/` 등)에 두고 격리 저장소에 넣지 않는다 |
| 게이트 실행 원본 전체 | 발췌만 (`WORK-ORDER.md` 의 해당 항목에) |

## 쓰는 때

슬라이스 종료(S10) 때 그 슬라이스에서 새로 생긴 하네스 · 환경 유형 문제마다: 재현을 만들 수 있으면 `repro/` 에 추가하고, `WORK-ORDER.md` 에 항목을 더하거나 갱신한다.
