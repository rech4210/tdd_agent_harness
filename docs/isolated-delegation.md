# 격리 위임

구현자가 **작업 지시서와 잠긴 테스트만** 보고 일하게 하는 절차다. 구현자는 하네스의 방어 장치(우회 패턴, 고친 구멍, 회귀 후보, 레드팀 기록, 결정의 배경 보고서)를 모른다. 정보 조건을 고정해야 "하네스가 구현자를 붙잡는가"를 측정할 수 있다. 잠금과 판정은 main에만 있다.

이 절차는 어떤 에이전트 도구에도 의존하지 않는다. 사람이 여는 대화형 세션, 에이전트 CLI의 비대화형 모드, 위임 도구 중 무엇을 써도 된다.

## 1. 절차

| # | 단계 | 할 일 | 확인 |
|:---|:---|:---|:---|
| 1 | 기준 확인 | 기준 태그 `<slice>-base` = 테스트 잠금 + 지시서 확정 커밋 | main에서 잠금 검사가 통과 |
| 2 | 꺼낼 목록 | 지시서 §2(읽기 허용) + §3(쓰기 허용) + 빌드 · 실행에 필요한 최소 설정 | 아래 "넣지 않는 것"이 목록에 없다 |
| 3 | 격리 저장소 만들기 | 기준 태그에서 목록만 꺼내 **별도 저장소**를 만들고 첫 커밋 | 첫 커밋 = 구현자 diff의 기준 |
| 4 | 명세 사본 | 구현자가 읽어야 할 외부 문서가 있으면 사본을 격리 저장소 **안에** 둔다 | 위임 도구가 작업 공간 밖 읽기를 거부할 수 있다. 권한 전체 해제로 풀지 않는다 |
| 5 | 위임 | 아무 에이전트 도구로. 입력은 지시서 한 장. 위임 도구가 편집 뒤 지시서 `feedback` 명령을 돌려 결과(`reports/feedback_report.json`)를 에이전트에게 돌려주는 루프(내부 반복 상한 예: 3)를 둘 수 있다. 에이전트에게 명령 권한은 주지 않으며(HD-09), 커버리지(G3)는 피드백에 넣지 않는다(구현자가 분기를 지우는 왜곡 방지). 피드백 게이트 명령은 커버리지를 출력하지 않는다 (파일로만, 그 파일은 피드백 뒤 지운다). 반복 수는 위임 기록에 남기고, 하네스 KPI 는 `config/delegation.toml` 의 `feedback_key` 로 읽는다 | 사람은 지시서 밖의 지시를 하지 않는다 |
| 6 | 회수 | 격리 저장소에서 **쓰기 허용 경로의 diff만** 패치로 만든다 | 그 밖의 변경은 버리고 기록한다 (G0 위반 지표) |
| 7 | 적용 | main에 패치를 적용하고 커밋 | 패치가 쓰기 허용 경로만 건드린다 |
| 8 | 판정 | main에서 게이트 명령 (`python harness/run_gates.py --role implementer --base <slice>-base --slice <slice> --cause implementer|test|harness`). **G3(커버리지) 실패는 테스트 작성자가 먼저** "테스트 빈틈 / 구현자의 쓸모없는 코드"를 판정. **시각 · 난수를 쓰는 슬라이스는 diff 읽기 항목에 "시계 · 난수 · 환경 직접 접근" 고정** (정적 검사 G1 은 이름의 마지막 두 마디만 본다는 한계) | 위임 도구 · 에이전트의 성공 보고는 판정에 쓰지 않는다. 테스트 빈틈이면 테스트 보강 · 재잠금(H3)으로 넘기고 구현자 회차로 세지 않는다 |
| 9 | 수정 루프 | 구현자 원인 실패만, 실패한 게이트 이름과 메시지를 전달. 구현자에게 넘길 때 기본 문구: **"명세가 요구하는 분기는 지우지 말고 보고"** | 방어 장치의 설명을 붙이지 않는다. 테스트 · 하네스 원인은 구현자에게 돌려보내지 않는다 (구현자가 커버리지를 맞추려고 명세 요구 분기를 지우는 왜곡 방지) |

### 넣지 않는 것

| 경로 · 자료 | 이유 |
|:---|:---|
| `harness/`, `adapters/` | 우회 패턴과 판정 로직 |
| 결정 기록의 배경 보고서, 문제 기록, H3 승인 자료, 검토 · 레드팀 보고서 | 고친 구멍과 남은 빈틈이 적혀 있다 |
| 회귀 세트 · 검증 빌드 | 정답 구현이다 |
| 계산 오라클이 든 테스트 지원 모듈 | 구현자가 코드를 그대로 옮겨 오라클과 구현이 같은 맹점을 공유하게 된다 (H-09, 이슈 #30). 오라클은 기대값 표 · 성질이 기본이며, 계산 오라클이 든 모듈은 격리 저장소에 주지 않는다 |
| 다른 슬라이스의 지시서 | 지시서는 슬라이스마다 유일한 계약이다 |
| 잠금 파일 · 판정 보고 | 격리 저장소에서는 잠그지도 판정하지도 않는다 |

## 2. 명령 예 (POSIX 셸)

```sh
BASE=<slice>-base
WORK=../<project>-impl-<slice>          # 프로젝트 작업 트리 밖
PATCH="$WORK.patch"                     # 패치도 작업 트리 밖에 둔다 (G0 가 새 파일로 집계하지 않게)
mkdir -p "$WORK"
git archive "$BASE" -- <읽기 · 쓰기 허용 경로 목록> | tar -x -C "$WORK"
git -C "$WORK" init -q && git -C "$WORK" add -A && git -C "$WORK" commit -qm "base: $BASE"

# ... 위임 (아무 도구) ...

git -C "$WORK" add -A
git -C "$WORK" diff --cached HEAD -- <쓰기 허용 경로 목록> > "$PATCH"
git -C "$WORK" diff --cached --stat HEAD                   # 허용 밖 변경이 있었는지 확인 · 기록
git apply --check "$PATCH" && git apply "$PATCH"           # main 에서
```

Windows PowerShell에서는 `git archive --format=zip -o base.zip $BASE -- <경로>` 후 `Expand-Archive`를 쓴다. Core 추출 후에는 `harness workspace`가 2 · 3 · 6단계를 맡는다(예정).

## 3. 함정

| 함정 | 증상 | 대응 |
|:---|:---|:---|
| 위임 도구의 거짓 성공 | 권한 거부로 아무것도 못 했는데 "성공" | 결과는 diff와 게이트로만 판단. 빈 diff = 실패 |
| 작업 공간 밖 읽기 거부 | 비대화형 실행에서 명세를 못 읽고 보고 없이 종료 | 4단계: 사본을 격리 저장소 안에 |
| 대화 이어 가기의 경로 어긋남 | 수정 회차가 **이전 회차의 작업 경로**에 쓰려다 거부됨. 대화 기억 속 코드와 새 작업 공간의 파일이 다름 | 같은 작업 공간을 재사용하거나, 새 회차의 첫 메시지에 작업 경로를 명시. 이전 회차 변경이 새 작업 공간에 들어 있는지 확인 |
| 위임 도구가 프로젝트 작업 트리에 기록을 남김 | 다음 작업자의 G0가 "허용 경로 밖 변경"으로 실패 | 기록 위치를 저장소 밖으로, 또는 `.git/info/exclude`. 프로젝트 설정 파일은 건드리지 않는다 |
| 격리 저장소에서 잠금 · 판정 | 판정의 신뢰가 사라진다 | 잠금 · 판정은 main에만 |
| 하네스 설계자가 구현자 | 방어를 아는 구현 → 측정 오염 | 배정 금지 (`templates/role-assignment-analysis.md`) |
| 위임 도구 실패 회차 | 구현자의 재시도 수가 부풀려진다 | 환경 유형으로 문제 기록, 구현자 KPI에서 제외 |

## 4. 기록

| 무엇 | 어디 |
|:---|:---|
| 격리 저장소 이름, 위임한 에이전트, 회차 | 종료 기록 머리말 · 경과 |
| 허용 밖 변경 (버린 것) | 종료 기록 KPI "G0 위반" |
| 위임 도구 문제 | 문제 기록 (환경) |
